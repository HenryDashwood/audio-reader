# Browser capture reliability

The capture pipeline has one shared policy (`scripts/capture_policy.js`), one
pinned Readability bundle, and native review flows. The bundle is generated by
`python3 scripts/build_safari_capture.py`; Android packages that same artifact.

## Outcomes and user control

- **Captured:** visible article text was extracted and passed the identity,
  ambiguity, and paragraph-preservation checks. This is evidence of extraction,
  not a promise that a publisher supplied the entire article. Both clients say
  so in their review copy.
- **Sign-in required:** a visible membership gate was detected. Android offers
  the in-app browser; Safari sharing asks the user to return to Safari, sign in,
  and share again. Neither automatically queues the gate as article text.
- **Uncertain:** an address mismatch, missing/ambiguous/incomplete body, excessive
  size, failed load, or timeout requires review. Android does not finish an
  already requested save when background extraction becomes uncertain.
- **Save link only:** an explicit user choice. The existing backend may try the
  address independently; a link-only save does not certify successful capture.

Android always offers a manual website capture action for HTTPS shares, even
when text was returned. Its browser sessions are separate from Chrome. Signing
in never bypasses the publisher's access controls. Page navigation invalidates
in-flight extraction. Two matching automatic snapshots, one second apart, are
required; changing content receives an uncertain result after three attempts.
The overall preparation timeout remains 20 seconds. A separate Android test
checks a paywall appearing after the first readable snapshot.

## Policy boundaries

All host/platform decisions for browser capture live in `capture_policy.js`:

| Policy | Evidence and scope |
| --- | --- |
| Substack identity | Platform hostname or its application bundle on the loaded page; only known navigation flags and the parameters Substack adds to email links (`publication_id`, `post_id`, `isFreemail`, `r`, each in its own value shape) on `/p/` paths are ignored. Elsewhere only `utm_*`, `fbclid`, `gclid`, `mc_cid` and `mc_eid` are. |
| Ghost membership | Generator metadata plus a visible gate; general visible access-instruction checks also cover unfamiliar themes. |
| General membership | A visible access instruction and action inside content or a dialog. Generic newsletter invitations, hidden templates, quoted instructions, and paid-content metadata alone are insufficient. |
| Failed navigation recovery | Only a rejected main-frame GET with HTTP 400 and the exact structured query-validation error for repeated `open=false`; no publication hostname checks or blanket query normalization. |
| Archive identity | Explicit matching short-link metadata and timestamped snapshot identity. |
| Social title | Platform URL structure determines author attribution; it does not relax article identity. |
| Optional layout adapters | Existing Canary split-prose and Simon Willison illustrated-note adapters remain bounded layout exceptions. They do not determine access or recovery options. |
| MediaWiki article sections | Generator metadata, a single parser body and a matching primary heading identify the article. Current heading/body disclosures and older `mf-section` blocks are expanded in the capture copy; unrelated hidden elements and the original page state are preserved. |

There are no article-specific capture branches or new publication-domain
exceptions. Unknown sites use the general extractor. New exceptions need
representative positive and negative fixtures and a documented reason that the
general path is insufficient. Prefer structural evidence over additional domains.

Paragraph preservation compares each paragraph's own inline prose. A widget
injected inside a paragraph is not part of that paragraph's text evidence;
nested paragraphs are checked separately. This preserves meaningful omissions
while avoiding false failures when Readability removes widget controls.

When browser extraction loses paragraphs from a single semantic article whose
primary heading matches the page title, it retries inside that article with
layout divs unwrapped. The server starts with this bounded selection and falls
back to page scoring if it loses prose. Both paths still run their extractor
and must pass the original paragraph-preservation check. Ambiguous articles,
unmatched headings, access gates and genuinely truncated extraction do not gain
a raw-HTML fallback.
Language and direction attributes survive layout simplification.

The retry excludes explicit sidebars, footers and separately headed lists of
related links; a similarly named section with its own prose remains article
content. Accessibility-only annotations inside already labelled links are
removed consistently before extraction and comparison. Sole screen-reader link
labels and accessible text outside links remain intact. The server also protects
illustrated figures and their captions while selecting prose. These rules use
document structure and common accessibility conventions, with no BBC-specific
hostname, class or article branch.

MediaWiki pages, including Wikipedia, use their identified parser body directly
so section boundaries, references, lists, images and captions survive capture.
The shared script recognises both the current `mf-collapsible-content` structure
and older mobile section blocks. It removes collapse attributes only from
verified section bodies in the copy, without clicking controls, changing website
preferences or exposing independently hidden descendants. Article edit controls,
contents controls and navigation boxes are omitted. The usual address, access,
size and sanitisation checks remain in place.

## Repeatable checks

- `make android-check`: full Android compile, JVM tests, and lint.
- `ANDROID_SERIAL=emulator-5554 make android-test TEST=com.henrydashwood.magpie.IncomingSharingTest`:
  share lifecycle, queue/account isolation, navigation recovery, late paywalls,
  explicit fallback, sign-in/capture, and large-text presentation.
- `BrowserCaptureReliabilityTests` and `SafariCaptureTests`: native WebKit
  extraction, including the shared corpus in
  `ios/HearfulTests/BrowserCaptureFixtures/capture-policy-cases.json`.
- `CaptureUploaderTests`: share-pane upload and prepared-text acknowledgement,
  failed/unfinished save retention, cancellation, retry, and account isolation.
- `node scripts/capture/check.cjs`: the same corpus in Chromium. Requires an
  installed Playwright package and Chromium; set `NODE_PATH` if supplied by the
  workspace runtime. Add `--live` for the anonymous read-only site matrix.
- `make backend-check` also checks that the generated Safari bundle matches its
  sources. No server API or frozen released-client baseline is changed here.

The corpus includes unknown domains, Substack custom domains, multiple Ghost
layouts, WordPress/Blogger metadata, semantic and non-semantic article bodies,
hidden gates, ordinary newsletter prompts, quoted access instructions,
empty/login pages, competing articles, pagination, stale identity, and malformed
navigation failures. Synthetic fixtures establish behavior, not publisher access.

## Completing saves in the iOS share pane

The share extension now uploads the durable capture through the existing saved
article API and checks the returned article's exact content version for readable
text before displaying **Saved to Magpie**. Magpie does not need to be running.
Existing installations must open the updated app once while online to connect
the share pane to their verified sign-in. The credential is held in the existing
app group's Keychain access group; it is never written into capture queue files.
Signing out clears it, and account changes stop an in-flight capture from being
sent to the new account.

Keep the pane open until saving finishes. Network or preparation failures show
**Save not finished** and **Retry**, retaining the original capture. **Finish
later** or dismissal cancels the foreground upload and leaves unfinished work
for the main app's existing queue. Retrying in the same pane reuses that capture.
A link-only save cannot report preparation success unless readable text is
returned. This does not certify that a publisher supplied its full article.

## Android website sign-in and article boundaries

Visible capture uses a full-size WebView so CSS viewport units and sign-in dialogs
have a real viewport. Client-side history changes update the displayed address
and invalidate previous extraction work.

One user-initiated child WebView may open while retaining the publisher as its
opener. Its address is visible, **Close window** returns to the parent, and
article capture stays disabled until the child closes. The parent retains its
viewport and JavaScript context while being hidden from accessibility. Disposal
destroys both views; returning to the parent invalidates old capture work.
Hidden capture, nested windows and unsolicited popups are rejected. Browser
origin rules apply without a native bridge, user-agent spoofing or extra cookies.

This window lifecycle does not guarantee identity-provider support. Some providers
reject embedded browsers. A Chrome/Custom Tab session has separate cookies and
cannot establish that the capture WebView is signed in. Test the chosen
publisher's sign-in and full article on the intended device.

A correct opening preview does not prove a correct full save. For non-semantic
layouts, the extractor identifies the story around its unique title-matching
heading and excludes separately headed recommendation branches and outside
feeds. It retains sibling story sections, quoted headings and ordinary article
subsections, then compares preserved prose. These rules do not use publisher
names or article-specific IDs/classes. Shared unknown-domain fixtures cover
recommendations, split story sections, poetry, images, lists and teasers.

## Device acceptance

Use the repeatable checks above for regression coverage. On the intended phone,
verify website sign-in, navigation, popup return/cancellation, article preview,
offline queue retention, upload and reader fetch. Compare the complete saved
body with the source, including the final paragraph, images and captions; do not
stop after inspecting the opening. Preserve existing accounts and website cookies.
Test Safari sharing and Android capture separately, including VoiceOver/TalkBack.

## Remaining limits

A sufficiently delayed gate, unrecognized language/layout, CAPTCHA, or publisher
that returns a plausible teaser without any gate can evade automatic detection.
That is why captured text is not labelled complete and manual capture remains
available. The settling heuristic cannot prove that all future page scripts have
finished. JavaScript navigation recovery requires the observed error response;
other failures remain explicit instead of guessing URL changes. Existing server
link fetching and physical Safari sharing are separate verification surfaces.
Do not infer TalkBack, physical Safari, every subscription provider, or complete
end-to-end save quality from synthetic regression coverage.
